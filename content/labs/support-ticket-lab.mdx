This lab builds a support ticket system the way a real implementation should start: schema-first. You will design a Dataverse data model, surface it in a model-driven app, and layer on the validation and calculation logic that keeps the data honest.

By the end you will have a working ticket system and, more importantly, a pattern you can apply to any relational business requirement.

## What you will build

A support ticket system with:

- **Tickets** linked to customers and support agents
- **Ticket updates** as a child table with automatic timestamps
- **Status and priority lookups** as reference data
- **Business rules** that enforce state transitions and required fields
- **Calculated and rollup fields** that summarize ticket history

## Modules

### Module 1: The Data Model

Design the Dataverse schema that everything else rests on. You will create the core tables, establish relationships, and configure the alternate keys and constraints that make the model self-enforcing.
