# Content Style

How powerplatform.fyi writes.

## Article shape

Every substantive piece includes:

- Problem
- Why it matters
- Practical architecture pattern
- Common mistakes
- Example
- Decision checklist
- Related articles

## Language

- Say the specific thing: name the control, the API, the table, the setting.
- Banned words: unlock, transform, supercharge, revolutionary, game-changing, seamless, leverage (as a verb), empower.
- "Citizen developer" is fine; "low-code will change everything" is not.
- Opinion is allowed when it is earned: state the trade-off, then the recommendation.
- Short paragraphs. Headings that carry information, not suspense.

## Code and config

- PowerShell, JSON, and KQL blocks get language tags and must be copy-paste runnable.
- Names in examples are realistic (`contoso-prod`, `cr4b2_...`), never `foo`/`bar`.
